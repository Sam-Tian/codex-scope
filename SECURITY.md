# Security Policy

## Supported Versions

CodexScope is pre-1.0. Security fixes are targeted at the latest commit on the default branch and the latest published package version, when one exists. Older commits and unpublished local builds are not guaranteed to receive backports.

## Reporting A Vulnerability

Please do not open a public issue for a vulnerability if it includes exploit details, sensitive project data, secrets, tokens, cookies, private keys, environment values, raw transcripts, full tool output, or full logs.

Use GitHub private vulnerability reporting if it is enabled for the repository. If private reporting is unavailable, open a minimal public issue that says you have a security report to share, but do not include sensitive details. A maintainer can then coordinate a safer disclosure path.

Helpful reports include:

- affected version or commit
- operating system and Node.js version
- high-level impact
- minimal redacted reproduction steps
- whether generated `.codex-architecture/` state is involved

Please keep all examples redacted.
